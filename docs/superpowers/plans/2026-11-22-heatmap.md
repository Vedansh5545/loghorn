# Latency Heatmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use orchestrating-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fourth explore view, Heatmap (span count by time × log-duration band, Spans mode), with a selectable cell that narrows a Spans / Grouped list below, plus an "All kinds" stream (`*`) and the p90 and error_rate metrics.

**Architecture:** The server gains stream `*` (every stream of a source), `view: "heatmap"` in `query.Run` reusing the graph's x-axis, a `cell` selection applied half-open on raw values, and two metrics. The page adds the All kinds row, the Heatmap tab, a `heatmap.js` SVG chart, a shared splitter module, and a lower pane that reuses the single result area for the Spans (samples query) and Grouped (table query) tabs.

**Tech Stack:** Go (net/http, `internal/query`, `internal/schema`), vanilla ES modules embedded with `go:embed`, Playwright MCP for browser checks.

**Spec:** `docs/superpowers/specs/2026-11-22-heatmap-design.md`

## Review Focus

1. A cell on a bucket boundary: a span whose time equals the next bucket's start is counted in exactly one cell, and the cell's list shows exactly the banner's count.
2. A range whose From falls mid-bucket: the first cell's list must not include spans before From (the page clips the cell's `from`).
3. `duration_ms` inferred as `int` (all whole numbers) or saved as a string type: the heatmap still bins and cell selection still works (no 400).
4. Spans with no `duration_ms`, zero or negative duration, or no time: zero/negative land in the lowest band; missing ones are counted in `skipped`, never in a cell.
5. Switching to Logs mode while on Heatmap, or loading a URL/favorite with `view=heatmap` in Logs mode: falls back to Samples without a 400 banner.

```go
// HeatCell narrows a query to one heatmap cell. Not saved with a favorite.
type HeatCell struct {
	From time.Time `json:"from"`         // inclusive
	To   time.Time `json:"to"`           // exclusive
	Lo   *float64  `json:"lo,omitempty"` // ms, inclusive; nil = no lower bound
	Hi   float64   `json:"hi"`           // ms, exclusive
}
// Query gains:  Cell *HeatCell `json:"cell,omitempty" toml:"-"`

type Heatmap struct {
	Bucket        string      `json:"bucket"`
	BucketSeconds float64     `json:"bucketSeconds"`
	Starts        []time.Time `json:"starts"`
	Bands         []Band      `json:"bands"`  // ascending
	Counts        [][]int     `json:"counts"` // [timeIndex][bandIndex]
	Max           int         `json:"max"`
	Total         int         `json:"total"`
	Skipped       int         `json:"skipped"`
}
type Band struct{ Lo, Hi float64 } // json "lo","hi", ms
// Result gains: Heatmap *Heatmap `json:"heatmap,omitempty"`

// xAxis is the graph's bucketing, shared by graph and heatmap.
func xAxis(timed []*record.Record, bucket string, from, to time.Time, loc *time.Location) (starts []time.Time, size time.Duration, name string, last time.Time, err error)
func bands(minMs, maxMs float64) []Band

```
