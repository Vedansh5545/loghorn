# CLI Query Export Implementation Plan

> **For agentic workers:** executed with the `orchestrating-plans` skill: one task runner per task, each with a fresh reviewer. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `loghorn <page URL>` exports a web view's data as csv/tsv/md/json/jsonl/yaml/toon (or DuckDB SQL with `-to-sql`), every `-web` instance is discoverable over a per-user unix socket, and the page's copy bars gain a format droplist.

**Architecture:** Formatting and SQL generation run in the server (`POST /api/query` with a `format` field); a new `internal/export` package turns a `query.Result` into text, and `query.ToSQL` turns a query plus its result into SQL. The CLI is a thin client over TCP or the unix socket. The page's main-view copy calls the same endpoint.

**Tech Stack:** Go (module `github.com/jimbeveridge/loghorn`), `encoding/csv`, `gopkg.in/yaml.v3` (already a dependency), `github.com/toon-format/toon-go` v1.0.1 (new), vanilla JS page in `internal/web/static/`.

**Spec:** `docs/superpowers/specs/2026-11-22-cli-query-design.md` — every task reads the sections it names.

## Global Constraints

- loghorn is public: never write `auction`, `taa`, `anvil-pulse` or any private app identifier into code, tests, docs or commit messages. Before each commit: `git grep -n -i -e auction -e taa -e anvil-pulse` on the changed files.
- Tests and demos never touch the real `~/.config/loghorn` or the real socket dir: set `HOME` and `TMPDIR` to `t.TempDir()` (or a scratch dir).
- Never pipe input into a `loghorn` binary while probing by hand (it records piped stdin to the project log); use `< file` or a scratch dir.
- Web handler tests use `httptest.NewServer` (the Host guard needs the listener's address). Number values in test records are `json.Number`.
- After `go get` of a module, run `go mod tidy`.
- Startup ordering (CLAUDE.md): validate everything that can `os.Exit` before launching a child; query mode never launches a child.
- Worktree sessions: no heredocs, no compound git commands (`git add … && git commit …`), never set `XDG_CONFIG_HOME`. Write scripts with the Write tool; run git commands one per call.
- Column names in every export are field paths, never labels. SQL types are exactly `VARCHAR`, `BIGINT`, `DOUBLE`, `BOOLEAN`, `TIMESTAMPTZ`, `JSON` (duration → `DOUBLE` with unit `ms`).
- Computed numbers are rounded to 15 significant digits and printed with `strconv.FormatFloat(v, 'g', -1, 64)`.
- Commit messages end with:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01BwT7CMvLEef4hMQT3Uea4r`

## Review Focus

1. Values containing tab, newline, `|`, `"`, `,`, backslash or non-ASCII, in every flat format: a reader must get the value back exactly (TSV escapes, CSV quoting, Markdown `\|` and `<br>`). — tests in Task 1.
2. Empty results (no rows, a graph with no series, a heatmap with no spans, `columns: null`): every format writes a valid, header-only document, never a crash or `null` where an array belongs. — tests in Tasks 1 and 2.
3. Filter values and field paths containing `'`, `"`, `%`, `_`, `\` reaching the SQL: always quoted/escaped, never injectable. — tests in Task 4.
4. Socket hazards: stale `<pid>.sock` from a killed instance, two live instances, a socket dir owned by another user or mode 0755: the CLI must not hang, mis-pick or connect through an unsafe dir. — tests in Tasks 6 and 7.
5. Agent shells: positional URL with stdin a pipe or `/dev/null`, `-url @-`: never treated as piped log input, never recorded, never launches anything. — tests in Task 7.
