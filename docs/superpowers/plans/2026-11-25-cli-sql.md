# CLI SQL (`loghorn query -sql`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `loghorn query -sql 'SELECT …'` runs read-only SQL against serve's DuckDB store through Jim's table model and prints the rows.

**Architecture:** serve builds the table model (`logs."<stream>"`, `spans."<stream>"`, `*` tables, `loghorn.this_run_*` macros) as views over `all_records`, reusing `Engine.Relation`'s typed conversion, and re-runs the DDL only when its text changes. A new socket-only `POST /api/sql` checks the statement with DuckDB's parser, runs it with a timeout and a row cap, and answers in an export format. The CLI sends `-sql` text there.

**Tech Stack:** Go, duckdb-go v2, existing `internal/export`, `internal/sock`.

**Spec:** `docs/superpowers/specs/2026-11-25-cli-sql-design.md` (and the table model in `query.SQLHeader`).

## Global Constraints

- Only `loghorn serve` opens the database; the CLI never opens `loghorn.duckdb`.
- `-sql` never writes, attaches, installs, or reads/writes files.
- Default row cap 1,000; `-limit N` overrides; a cut result notes it on stderr.
- Query timeout 30 s.
- Output formats for `-sql`: tsv (default), csv, md, json, jsonl. yaml, toon, sql are refused.
- Build/test with `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk`; tests never write the repo's `.loghorn/`.

## Review Focus

1. Two field paths that differ only in case (`Code`, `code`) → one column (the first), not a broken view set.
2. A stream name with `"` or `.` in it → the view is created and queryable as `logs."a""b"`.
3. Two `-sql` requests at once → both answer; no catalog write conflict.
4. An empty store → `SHOW ALL TABLES` answers; `FROM logs."app"` answers DuckDB's "does not exist" error.
5. A result of 100k rows → only `limit` rows are read, the note says so.

### Task 2: Table model views and macros

**Files:** Create `internal/duckstore/model.go`, Modify `internal/duckstore/read.go` (Relation with literal binding), Test `internal/duckstore/model_test.go`

**Interfaces:**
- Produces:
  - `type ModelTable struct { Source, Stream string; Fields []schema.Field }` (Stream may be `record.AllStreams`, named `*`).
  - `func (e *Engine) LatestRun(ctx context.Context) (id string, start time.Time, ok bool)` — newest record's `loghorn.run.id` and that run's earliest `_time`.
  - `func ModelDDL(tables []ModelTable, runStart time.Time, runID string) string` — `CREATE SCHEMA IF NOT EXISTS memory.logs/spans/loghorn`, `CREATE OR REPLACE VIEW`, `CREATE OR REPLACE MACRO`.
  - `func (e *Engine) ApplyModel(ctx context.Context, ddl string) error` — mutex; no-op when `ddl` equals the last applied.
  - `func (e *Engine) relation(source, service, stream string, cols []schema.Field, bind func(string) (string, []any))` behind `Relation`, so views get literals instead of `?`.
- View columns: `_id AS seq`, `timezone('UTC', _time) AS "time"`, `_service AS service`, `_text AS raw`, then per field `vi` as its quoted path; duration `round15(vi * 1000)` (helper SQL matching `query.Round15`), timestamp `timezone('UTC', vi)`. Skip fields named seq/time/service/raw (case-insensitive) and later case-duplicates.

- [ ] **Step 1: Write tests** on an engine fed log records (stream `app`: `code` int, `latency` duration `"12ms"`, one bad `code:"oops"`, `Code` duplicate) and spans (`http.server`):
  - `TestModelViews`: `information_schema.columns` for `logs.app` = seq BIGINT, time TIMESTAMP WITH TIME ZONE, service VARCHAR, raw VARCHAR, code BIGINT, latency DOUBLE; `spans."*"` exists.
  - `TestModelValues`: `SELECT code, latency FROM logs.app ORDER BY seq` → bad code NULL, latency 12.
  - `TestModelMacros`: `SELECT loghorn.this_run_id(), loghorn.this_run_start()` = given id/start; NULL id when none.
  - `TestApplyModelSkipsSameDDL`: second Apply with same text runs no statement (count via a hook or `duckdb_views()` creation unchanged).
  - `TestModelOddNames`: stream `a"b.c` → `SELECT count(*) FROM logs."a""b.c"` works.
